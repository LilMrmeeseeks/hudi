## 五、v4 定稿：固定双窗 + 左窗纵向跟随（2026-11-12 晚）

用户否决 v3 的推近（左窗放大到 1.48× 会把思维链左右切边，「COT 内容显示不全」），也否决了右窗推进。
**结论：不做任何推近，只保证 COT 完整可读。**

| 部件 | 做法 |
|---|---|
| 底图 | `crop=1728:968:0:112, scale=1920:1080, eq=brightness=-0.05:saturation=0.94`，压暗 50% 遮罩 |
| 遮罩 | `hole_dual.png`：洞A (70,60,830,560) r24、洞B (960,60,700,394) r24，alpha 126，各带 30px 柔影 + 1.6px 白边 |
| 左窗 | `crop=735:497:x=135:y='min(300+VS*t,583)'` → `scale=830:560` → `pad=852:582:11:11` → `overlay=59:49` |
| 右窗 | `crop=757:426:x=919:y=216` → `scale=700:394` → `pad=722:416:11:11` → `overlay=949:49` |

要点：
- **宽度锁死 735、x 锁死 135**——这是唯一能同时容下「ARGUS 正在思考」的 A 和气泡右沿的宽度，任何横向推近都会切字。
- 纵向靠 `y` 递增跟随内容滚动（cv1/cv4 用 22px/s，cv2/cv3 用 24px/s），`min(...,583)` 防止越界。
- 右窗完全不推、不裁，固定显示整块监控画面（猫一直在走）；底图压暗后它读作「放大镜」。
- 放大倍率只剩 735→830 = **1.13×**，是「把这块提出来看」而非「特写」。

构建脚本：`build\cv-push.ps1`（一次跑四段，含海报从 raw 5.6s 抽帧）。
字幕：`C:\Users\MeeCreeps\_v\ass\cv1..4.ass`。

**ASS 三条硬坑（都踩过）**：
1. 用 `$hdr + $arr` 拼数组时，若 `$arr` 是嵌套数组（每个元素本身是数组），`WriteAllLines` 会把内层数组 `ToString()` 成空格连接的一行 → 整行 `Dialogue:` 被 libass 当成字幕文本打在画面上。必须逐行 `ArrayList.Add()`。
2. Band 的 drawing 必须用**相对坐标**：`{\an7\pos(0,896)\p1\bord0\shad0}m 0 0 l 1920 0 l 1920 184 l 0 184`。写成 `\pos(0,0)` + 绝对坐标会画到屏幕外；写成 `\pos(0,896)` + 绝对坐标会出现**斜边**。
3. PowerShell 变量名大小写不敏感：`$SRC` 与 `$src` 是同一个变量，`$src=Join-Path $SRC $f` 会把根目录覆盖成第一个文件的完整路径，后面几段全部 `MISSING`。改名 `$SRCDIR`。
